## 2. 设计 Skill 遵守清单（b2b-admin + 普通模式）

架构 §0 决策：项目类型 `b2b-admin`、设计模式 `普通` → 不出方向稿、不按方向稿实现；但 5B 仍按 `skills/README.md` 的「按项目类型必读」读三个 active Skill，并把约束落到 token 与组件。

| Skill | 关键约束 | 本项目做法 | 落点 |
|---|---|---|---|
| design-skill-master | 先定 token；一屏一件事；真实数据；不做无意义装饰 | `theme/tokens.ts` 先落色/间距/字号；每屏一个主任务；统计只显示真实周数据 | `src/theme/tokens.ts` |
| taste-skill | 单色强调、中性界面；数据用强色；禁渐变/玻璃/阴影堆叠；无图标圆片；空/错/加载真实呈现 | 深松绿唯一强调色；卡片 1px 边框不投影；文字型底栏；三态组件与 Toast | `components/`、`screens/` |
| qiaomu-design / app-screens §12 | 8pt 网格；44px 触控；375/414 不横向溢出；KPI 用排版不做仪表盘；诚实空态 | 间距 4/8/12/16/20/24/32；Stepper/按钮 ≥44；SafeArea + 20px 边距；统计页纯 View 柱图 + 零数据文案 | `components/Screen.tsx`、`Stepper.tsx` |

补充口径：
- 未使用紫色/靛色主色、渐变、毛玻璃、AI 风插画、假 KPI、假头像。
- 管理页用「只读 + 脱敏」文案，避免暗示管理员能改他人数据。
- 登录页不写死演示验证码，只提示「见服务端 .env 的 DEMO_CODE」。

## 3. 路由与登录守卫（D-01 / D-02）

```
SafeAreaProvider
└─ QueryClientProvider
   └─ AppShell
      ├─ hydrated=false → BootScreen（读 SecureStore）
      ├─ token=null → AuthStack（Login）
      └─ token≠null → Stack
         ├─ MainTabs：Plans / Stats / Profile（文字型底栏）
         ├─ Workout  { planId, planName }
         ├─ Log      { planId, exerciseId, targetSets, targetReps, ... }
         └─ Admin
```

- 守卫为 `token` 条件渲染，不做手动 `navigate` 循环；401 清 token 后由状态自动回登录页。
- `queryClient.clear()` 在 token 变空时执行，防止下一个账号看到上一个账号缓存。
- 6 个业务页 + 1 个 admin 子页，与架构偏差 §6 第 6 条一致。

## 4. 请求层（D-03 / T-208）

`src/api/client.ts` 是唯一请求出口，页面不裸 `fetch`。

| 能力 | 实现 |
|---|---|
| Base URL | `EXPO_PUBLIC_API_BASE_URL` 优先；否则从 Expo `hostUri` 推导同机 `8094`；Android 模拟器回落 `10.0.2.2` |
| 超时 | 8s，`AbortController` + `setTimeout` |
| GET 重试 | 仅 GET、仅网络/超时，重试 1 次；`console.info('[api] GET ... 重试 1/1')` 可数 |
| Token | `useAuthStore.token` → `authStorage.getToken()` 兜底，`Authorization: Bearer` |
| 401 | `40101` / HTTP 401 → `clearSession()` → 状态自动回登录页 + Toast「登录已过期」 |
| 错误码 | `errors.ts` 映射 10 个业务码 + 网络/超时/格式异常；`AppError` 带 `code/httpStatus/field` |
| 响应校验 | 统一 envelope；非 JSON/缺 code/message 一律 `ERR_BAD_RESPONSE`，不泄露堆栈 |

- 403 与 401 分开：40301 只提示无权限，**不清登录态**。
- 请求层不打印 token；日志只出现方法与路径。

## 6. 页面行为与边界

### 6.1 登录（D-04 / T-103）
- 手机号：仅数字、11 位、`^1[3-9]\d{9}$`；不合法不发请求。
- 发送：`cooldown` 取服务端返回；42901 时本地也置 60s，防连点。
- 验证码：6 位；40102 内联红字，不跳页。
- 登录成功：`signIn` 写 SecureStore + 读缓存用户，清 Query 缓存；错误用 Toast。
- 演示码不在客户端出现。

### 6.2 计划（D-05 / T-104）
- 两查询：`plans` 三卡 + 本周次数；`current` 今日分化与动作数。
- 今日卡：浅强调底 + 强调描边 + 「今天」标签，不使用图标圆片。
- 空/错：空态给「seed 演示账号自带三份计划」；错误可重试。

### 6.3 今日训练（D-06 / T-302）
- `FlatList`：`keyExtractor` + `memo` 行 + `windowSize=7` + `initialNumToRender=12` + `removeClippedSubviews`。
- 固定行高 `64`，`getItemLayout` 与样式同源；行内不动态高度。
- `EXPO_PUBLIC_PERF_FIXTURE=1` 时在真实动作后拼 100 条夹具（负数 id，不参与提交，点击提示「只用于滚动采样」）。
- 空态：该计划无动作时提示回计划页/检查 seed。

### 6.4 记录（D-07 / D-08 / T-303 / T-304）
- 进入页面 `POST /workouts/start`（同用户同日由后端复用，前端不重复创建）。
- 行状态机：`idle → pending → saved`，失败 `error`（红边框 + 「重试保存」，保留已填重量/次数）。
- 重量 ±2.5kg（0–500），次数 ±1（1–50）；本地先改，已保存行 450ms 防抖 PATCH；新行点「完成这组」才 POST。
- 新行/已保存行都以 `(exerciseId,setNo)` 语义提交；重复点不会产生第二条（后端复合唯一键）。
- 顶部总容量来自服务端响应，不在客户端估算；`finish` 成功后禁用输入并刷新统计缓存。
- 订阅失效：`stats/weekly`、`stats/history`；不失效当前 workout 详情，避免编辑中被重置。

### 6.5 统计（D-09 / T-502）
- KPI 用排版：打卡天数 + 总容量，不做四宫格仪表盘。
- 4 周柱图纯 View：按 `max(volume)` 计算高度；0 数据保留 2px 基线与「本周还没打卡」文案。
- 历史列表展示最近 4 周；历史接口失败只降级提示，不遮住 KPI。

### 6.6 我的（D-10 / D-13 / T-403）
- `me` 失败时回退本地缓存用户；脱敏号来自服务端（示例 `139****9000`）。
- 角色徽标 `普通用户 / 管理员`；管理员才出现「全站打卡」入口。
- 退出：Alert 二次确认 → `signOut()` 清 SecureStore/AsyncStorage → 清 Query 缓存 → 回登录。
- SecureStore 不可用（Web/Keystore 异常）自动降级 AsyncStorage，并保留同一 key 语义。

### 6.7 Admin（D-11 / T-601 / T-603）
- 入口仅 `role=admin` 显示；非 admin 手改路由也会收到 40301 并显示「无权限访问该资源」。
- 汇总 3 项：用户数 / 训练数 / 总容量；打卡列表 10/页，上一页/下一页禁用态。
- 手机号只显示服务端脱敏值；接口只读，不提供编辑按钮。
- `size` 上限由后端 50 兜底，前端固定 10。

### 6.8 版本检查（D-12 / T-702）
- 启动 `GET /app/version`（`retry:false`，失败静默，不阻塞主界面）。
- 比较 `data.buildNo > expoConfig.android.versionCode` 才弹 Modal；本地 `1`、远端 `1` → 不弹。
- 「去下载」`Linking.openURL(apkUrl)`，失败 Toast；「稍后」关闭。
- 覆盖安装保留登录态的前提是同包名同签名（EAS keystore，见架构 §11）。

## 8. 安全与隐私

- 客户端无任何密钥、无 `DEMO_CODE`、无 JWT secret；登录页只提示「见服务端 .env」。
- Token 仅存 SecureStore（降级 AsyncStorage），不写 console、不进 URL。
- 业务错误只展示中文文案，不向用户抛堆栈/traceId。
- 管理员入口前端隐藏 + 后端 403 双层；前端不缓存 admin 列表跨账号，登出即清 Query。
- 手机号只使用服务端脱敏值；前端 `maskPhone` 仅作纯函数单测与本地展示兜底。
- `security_scan_secrets.py --sast` 结果：`✅ 生产代码未发现硬编码密钥`、`✅ 未发现已知代码级风险模式`。
