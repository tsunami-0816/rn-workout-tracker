## 3. 核心业务链路（端到端）

### L1 登录

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 手机号文本框 | 前端校验 `^1[3-9]\d{9}$` | 不合法 → 字段红字，不发请求 |
| N2 | 合法手机号 + 点「获取验证码」 | `POST /api/auth/send-code` → 内存频控（同号 60s 1 次） | `code=0`；演示环境提示「验证码固定 123456」 |
| N3 | 手机号 + 6 位码 | `POST /api/auth/login` → AuthService 校验（`123456`）→ `users` upsert（不存在建 `role=user`）→ JWT 签发（HS256 / 7d / sub,role,phone） | `{token, expiresIn, user{id,nickname,role}}` |
| N4 | token | 前端 `SecureStore.setItemAsync('auth_token')` + Zustand 写入 → `GET /api/auth/me` 预取 | 进入 MainTabs；杀掉 App 重开仍免登录 |
| N5 | 任意接口 401 | apiClient 清 SecureStore + Zustand → 清 React Query 缓存 | 跳登录页 + Toast「登录已过期」 |

### L2 计划查看

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | JWT | `GET /api/plans` → 按 `user_id` 查 3 条计划（push/pull/legs）+ 本周各 plan 打卡次数 | 3 张计划卡 + 完成度 |
| N2 | 当天 weekday | `GET /api/plans/current` → `weekday % 3` 映射 day_type（周一三四…循环） | 今日推荐卡高亮 |
| N3 | planId | `GET /api/plans/{id}/exercises` → `order_no` 升序，返回 target_sets/target_reps | 进入今日训练页的初始动作清单 |
| N4 | 无计划数据 | 后端返回空数组（不报 500）；seed 保证演示账号有 3 条 | 计划页空态「暂无计划」 |

### L3 今日训练（列表性能 C02）

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | planId | 拉 `/plans/{id}/exercises`（真实 12–16 条） | 动作清单渲染 |
| N2 | 环境变量 `EXPO_PUBLIC_PERF_FIXTURE=1` | 客户端在真实数据后拼 100 条 mock（同 schema，id 为负数，仅性能模式） | 100 条列表，用于 C02 采样 |
| N3 | 100 条 | FlatList：`keyExtractor=id`、`getItemLayout`（行高 64）、行组件 `React.memo`、`windowSize=7`、`initialNumToRender=12`、`removeClippedSubviews` | 首屏 ≤300ms；Perf Monitor FPS ≥50 |
| N4 | 点某动作 | 路由到记录页，携带 `{workoutId, exerciseId, targetSets, targetReps}` | 记录页进入可录入态 |

### L4 记录与幂等提交（M6 核心）

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 进入记录页 | `POST /api/workouts/start {planId}` → 事务内 `SELECT` 当日 `(user_id, log_date)` 的 workout_log，无则插入 | `{workoutId, logDate, totalVolume}`（重复进入复用同一条） |
| N2 | 重量/次数 stepper | 前端 Zustand 乐观写入 `pending` 行 | 列表立即出现「待提交」行 |
| N3 | 点「完成这组」 | `POST /api/workouts/{id}/sets {exerciseId,setNo,weight,reps,done}` → 事务：`INSERT ... ON CONFLICT (workout_log_id,exercise_id,set_no) DO UPDATE` → 重算 `total_volume = SUM(weight*reps WHERE done)` → 更新 workout_logs | `{setLog, totalVolume}` |
| N4 | 连点 3 次同组 | 冲突键命中 → 走 UPDATE，不新增行 | 数据库中该组仅 1 行（M6），返回同一 totalVolume |
| N5 | 提交失败（网络/401/400） | apiClient 抛分类错误 → 前端回滚 pending 行 | Toast 中文原因 + 重试按钮 |
| N6 | 点「结束训练」 | `POST /api/workouts/{id}/finish` → `finished_at=now()` | 统计接口缓存失效，L5 立即可见 |
| N7 | 改/删某组 | `PATCH`/`DELETE /api/workouts/{id}/sets/{setId}` → 同事务重算容量 | 容量数字同步变化，不允许负数 |

### L5 统计

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | JWT | `GET /api/stats/weekly`：`COUNT(DISTINCT log_date)`（本周 ISO 周一–周日）、`SUM(total_volume)`、近 4 周 `date_trunc('week', log_date)` 分组序列 | `{days, totalVolume, series[4]}` |
| N2 | 同用户重复请求 60s 内 | 进程内 Map 命中直接返回（key `stats:{userId}:{weekStart}`） | P95 明显下降；写操作已 invalidate，不会读到旧值 |
| N3 | 前端 | 纯 RN `View` 画 4 根柱（高度 = value/max），不引图表库 | 4 周柱状图 + 数字卡 |
| N4 | 本周无打卡 | 后端返回 `days=0,totalVolume=0,series` 全 0 | 空态「本周还没打卡」而非报错 |

### L6 我的页与 admin 越权（C05）

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | JWT | `GET /api/auth/me` → 查 users，`phone` 脱敏为 `138****8000` | 昵称 / 脱敏手机号 / 角色徽标 |
| N2 | role=admin | 前端显示「全站打卡」入口；普通用户不渲染该入口 | UI 层隐藏（**不等于权限**） |
| N3 | 普通用户直接请求 `GET /api/admin/workouts` | `JwtAuthGuard` 通过 → `RolesGuard` 读 `@Roles('admin')` 元数据 → 403 | HTTP 403 `{code:40301}`（C05 用例 1） |
| N4 | 普通用户构造 `userId` 查他人数据 | 所有非 admin 查询只用 JWT `sub` 过滤，忽略 body/query 的 userId | 只能看到自己（C05 用例 2） |
| N5 | admin 请求 | 分页 `page/size`（默认 20）→ 全站 workout_logs + 脱敏手机号 | 列表 + 总数；越界页返回空列表 |

### L7 版本检查与覆盖升级（C08 / C09）

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | App 启动 | `GET /api/app/version` → VersionService 读 `release.json`（env 可覆盖） | `{version,buildNo,apkUrl,notes}`，P95 ≤200ms |
| N2 | 本地 `expo-constants.expoConfig.version` + `android.versionCode` | 与远端 `buildNo` 比较 | 落后 → Modal「发现新版本 1.0.1」；最新 → 静默 |
| N3 | 点「去下载」 | `Linking.openURL(apkUrl)` | 浏览器/文件管理器打开 APK 地址（本地留档或局域网地址） |
| N4 | 1.0.1 覆盖安装 | 同包名 `com.liuchen.rnworkout` + 同 EAS keystore + `versionCode` 递增 | 直接覆盖，不提示卸载；SecureStore 中 token 保留 → 进主界面（C08） |
| N5 | 回滚 | 低 versionCode 不允许覆盖 → 卸载后装旧包 | `10_交付/发布记录.md` 写清代价与步骤 |

### L8 Flutter 对照（C10 / C11）

| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|

## 5. 数据模型设计

### 5.1 表清单（严格 5 张业务表 · C04 口径）

| 表 | 作用 | 关键约束 |
|---|---|---|
| `users` | 账号与角色 | `phone` 唯一（单列） |
| `plans` | 用户的三日分化计划 | `user_id` 外键；`(user_id, day_type)` 普通索引 |
| `exercises` | 计划内动作 | `plan_id` 外键；`(plan_id, order_no)` 普通索引 |
| `workout_logs` | 一次训练（当日） | `user_id`/`plan_id` 外键；`(user_id, log_date)` 普通索引 |
| `set_logs` | 单个组次记录 | **`(workout_log_id, exercise_id, set_no)` 复合唯一** = 幂等核心 |

### 5.2 DDL（PostgreSQL 16）

```sql
CREATE TABLE users (
  id          BIGSERIAL    PRIMARY KEY,
  phone       VARCHAR(11)  NOT NULL,
  nickname    VARCHAR(32)  NOT NULL DEFAULT '训练者',
  role        VARCHAR(8)   NOT NULL DEFAULT 'user' CHECK (role IN ('user','admin')),
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  CONSTRAINT uk_users_phone UNIQUE (phone)
);

CREATE TABLE plans (
  id          BIGSERIAL    PRIMARY KEY,
  user_id     BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name        VARCHAR(32)  NOT NULL,
  day_type    VARCHAR(8)   NOT NULL CHECK (day_type IN ('push','pull','legs')),
  sort_no     SMALLINT     NOT NULL DEFAULT 0,
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_plans_user_day ON plans (user_id, day_type);

CREATE TABLE exercises (
  id           BIGSERIAL   PRIMARY KEY,
  plan_id      BIGINT      NOT NULL REFERENCES plans(id) ON DELETE CASCADE,
  name         VARCHAR(48) NOT NULL,
  target_sets  SMALLINT    NOT NULL CHECK (target_sets BETWEEN 1 AND 10),
  target_reps  SMALLINT    NOT NULL CHECK (target_reps BETWEEN 1 AND 50),
  order_no     SMALLINT    NOT NULL CHECK (order_no BETWEEN 1 AND 200)
);
CREATE INDEX idx_exercises_plan_order ON exercises (plan_id, order_no);

CREATE TABLE workout_logs (
  id           BIGSERIAL     PRIMARY KEY,
  user_id      BIGINT        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  plan_id      BIGINT        NOT NULL REFERENCES plans(id) ON DELETE RESTRICT,
  log_date     DATE          NOT NULL,
  total_volume NUMERIC(12,2) NOT NULL DEFAULT 0,
  finished_at  TIMESTAMPTZ,
  created_at   TIMESTAMPTZ   NOT NULL DEFAULT now()
);
CREATE INDEX idx_workout_user_date ON workout_logs (user_id, log_date DESC);

CREATE TABLE set_logs (
  id             BIGSERIAL    PRIMARY KEY,
  workout_log_id BIGINT       NOT NULL REFERENCES workout_logs(id) ON DELETE CASCADE,
  exercise_id    BIGINT       NOT NULL REFERENCES exercises(id) ON DELETE RESTRICT,
  set_no         SMALLINT     NOT NULL CHECK (set_no BETWEEN 1 AND 10),
  weight         NUMERIC(6,2) NOT NULL DEFAULT 0 CHECK (weight >= 0),
  reps           SMALLINT     NOT NULL DEFAULT 0 CHECK (reps >= 0),
  done           BOOLEAN      NOT NULL DEFAULT false,
  created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
  CONSTRAINT uk_set_logs UNIQUE (workout_log_id, exercise_id, set_no)
);
```

### 5.3 索引与约束理由

- `uk_set_logs`：**C04 那 1 个复合唯一约束**，也是 M6 幂等的最终防线（应用层 upsert + 数据库唯一键双保险）。
- `idx_plans_user_day` / `idx_exercises_plan_order` / `idx_workout_user_date`：查询路径固定（按用户取计划、按计划取动作、按用户+日期倒序取记录），走索引避免全表扫。
- **口径说明（重要）**：设计书 §11 另列了 `exercises(plan_id, order_no)` 与 `workout_logs(user_id, log_date)` 两个唯一约束；本设计改为**普通索引 + 应用层 select-first**，理由是 C04 的验收口径是「5 张表 + 1 个复合唯一约束」。若第 3 步评审要求恢复，只加索引不加表，C04 的「1 个」需同步改口径（属基线变更，需用户拍板）。
- 字段规范：主键 BIGSERIAL；时间统一 `TIMESTAMPTZ`；重量/容量用 `NUMERIC`（不用 float，避免 0.1+0.2）；`check` 约束挡住脏数据；中文注释写到 Prisma schema 的 `///`。

### 5.4 幂等与容量口径

```sql
-- 组次写入（同一 workout + 动作 + 组号重复提交）
INSERT INTO set_logs (workout_log_id, exercise_id, set_no, weight, reps, done)
VALUES ($1,$2,$3,$4,$5,$6)
ON CONFLICT (workout_log_id, exercise_id, set_no)
DO UPDATE SET weight = EXCLUDED.weight, reps = EXCLUDED.reps,
              done = EXCLUDED.done, updated_at = now();

-- 同事务重算容量（只算已完成组）
UPDATE workout_logs w
SET total_volume = COALESCE((
  SELECT SUM(s.weight * s.reps) FROM set_logs s
  WHERE s.workout_log_id = w.id AND s.done = true
), 0)
WHERE w.id = $1;
```

- 统计口径：**本周 = ISO 周（周一 00:00 至周日 23:59，Asia/Shanghai）**；打卡天数 = `COUNT(DISTINCT log_date)`；总容量 = `SUM(total_volume)`；近 4 周序列 = `date_trunc('week', log_date)` 分组。
- `POST /workouts/start` 用「先查当日记录，无则插入」；并发双击由前端禁用按钮兜底（无唯一索引）。若第 7 步联调发现并发双开，再补 `(user_id, log_date)` 唯一索引并同步改 C04 口径。

## 6. 接口规范定义

### 6.1 统一请求 / 返回

请求头：

```
Content-Type: application/json
Authorization: Bearer <JWT>          # @Public 接口可不带
```

返回体（业务结果统一 HTTP 200；鉴权失败 401、越权 403、未找到 404、限流 429）：

```json
{ "code": 0, "message": "ok", "data": { }, "traceId": "b3f1c0e2" }
```

- `ResponseInterceptor` 统一包 `{code,message,data,traceId}`；`HttpExceptionFilter` 把抛出的异常映射到 §6.2 的 code。
- 分页统一：`data = { list, total, page, size }`；`page` 从 1 开始，`size` 默认 20、上限 50。

### 6.2 错误码

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 40001 | 400 | 参数校验失败（`data.field` 指出字段） | 字段红字 |
| 40002 | 400 | 状态不允许（如对已结束的训练再提交组次） | Toast「本次训练已结束」 |
| 40101 | 401 | 未登录 / token 过期 | 清 token → 跳登录 |
| 40102 | 401 | 验证码错误或过期 | 验证码输入框红字 |
| 40301 | 403 | 越权（非 admin 访问 admin 资源） | Toast「无权限访问」+ 返回 |
| 40401 | 404 | workout / plan / exercise 不存在 | 空态 + 返回 |
| 42901 | 429 | 验证码 60s 内重复请求 | 倒计时继续，提示稍后 |
| 50001 | 500 | 服务内部错误 | Toast「服务开小差」+ 可重试 |
| 50002 | 504 | 数据库超时 | Toast「数据库繁忙，请重试」 |

### 6.5 鉴权规则

- JWT claims：`sub`（user id）、`role`（user/admin）、`phone`；`exp` 7 天；HS256；secret 仅来自 `JWT_SECRET`。
- 守卫顺序：`JwtAuthGuard`（全局）→ `RolesGuard`（类/方法级）。`@Public()` 装饰器豁免：`send-code`、`login`、`app/version`、`health`、`docs`。
- **401 与 403 语义分开**：没登录/过期 = 401（前端跳登录）；已登录但角色不够 = 403（前端只提示无权限，不清登录态）。
- 数据归属：所有「我的」类查询只用 JWT `sub` 过滤，不接受客户端传 userId；admin 接口只做角色卡，不做数据归属。
- 验证码频控：内存 Map（phone → 最近发送时间），60s 内重复 → 42901；进程重启即重置（演示可接受）。
- **不能自助提权**：`login` 对不存在的手机号只建 `role=user`；`admin` 只由 seed 产生，任何接口都不接受客户端指定 role。
- CORS：dev 允许 `http://127.0.0.1:*` 与 `http://localhost:*`（Flutter Chrome 端口随机）；`acceptance` profile 收紧为固定来源，不长期放开。

### 7.2 发布拓扑（L7）

```
eas build -p android --profile preview
        │  云端 Gradle + EAS 托管 keystore（同项目复用）
        ▼
APK 下载链接 ──► 下载到 10_交付/apk/rn-workout-1.0.0.apk

        ▼
改 version 1.0.1 / versionCode 2 → 再 build → 覆盖安装 → 登录态仍在（C08）
```

- **签名**：一律用 EAS 托管的同一 keystore；若本地曾用自签 keystore，必须以同一把重新构建，否则覆盖安装报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
- **分发**：仅自用/局域网下载，不做应用商店、不做公网 CDN；`apkUrl` 可指向 `10_交付/apk/` 的本地路径或局域网 HTTP 地址，文档写清「面试演示用」。
- **回滚**：Android 不允许低 `versionCode` 覆盖 → 回滚 = 卸载 + 装旧包（登录态丢失），代价写进 `发布记录.md`。
