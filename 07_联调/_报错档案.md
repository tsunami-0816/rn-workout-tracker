## [11-25 17:00] 执行数据库重置时报 `--skip-seed` 不被识别

- 命令：`npx prisma migrate reset --force --skip-seed`
- 报错：打印 `prisma migrate reset` 的 usage/options 后 `reset exit=1`（未执行重置）
- 根因：本项目 Prisma **7.10.1** 不支持 `--skip-seed`（该 flag 非此版本选项；`package.json` 也未配 `prisma.seed`）
- 修复：去掉该参数执行 `npx prisma migrate reset --force`（exit 0，两迁移重放），再手动 `npm run seed`
- 关联：非产品缺陷；已写进 `07_联调/数据重置记录.md` §二备注，建议 step11 沉淀到工作流 prompts

## [11-25 16:58] admin 日期筛选传非法日历日返回 500

- 命令：`GET /api/admin/workouts?from=2026-13-01`（admin token）
- 报错：`HTTP 500`，`{"code":50001,"message":"服务内部错误，请稍后重试","data":null,"traceId":"b834761f"}`
- 根因：`admin.controller.ts` 的 `assertDate` 只做 `^\d{4}-\d{2}-\d{2}$` 正则，未校验日期语义；`toPrismaDate('2026-13-01')` 得到 Invalid Date → Prisma 抛错 → 500
- 修复：**本轮未修**（改 `05_代码/**` 会作废 G5 `4b357a5` 锚点；且属非核心 admin 筛选，不影响主链路）
- 关联：台账 **Q-012**（P2，`deferred`，第 8 步修：`assertDate` 加 `new Date(...)` 有效性判断 + 单测）

## [11-25 08:58] 探针 C-13 误报（psql 数值格式）

- 命令：`step7_probe.mjs R1` → C-13 `db=2.50`
