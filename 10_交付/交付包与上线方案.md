## 二、上线方案（局域网演示环境）

### 2.1 前置

- Windows 10/11 + Docker Desktop（WSL2 后端）；Node 22.23.2；npm 10+
- 手机与电脑**同一 WiFi**；Windows 防火墙放行 Node 的 8094/8096（专用网络）
- 重新出 APK 才需要 EAS CLI + Expo 账号（已登录 `liuchen`）；只演示现成 APK 则不需要

### 2.2 部署步骤（从零到可访问，约 10 分钟）

```powershell
# 1) 取代码
cd <项目目录>            # 含 05_代码/、10_交付/、docker-compose.yml

# 2) 起数据库（保留数据卷；首次会自动建库）
docker compose up -d pg
docker compose ps        # 期待 rn-workout-pg healthy

# 3) 后端环境变量（只在本机，禁止提交）
cd 05_代码\backend
Copy-Item .env.example .env
# 必填：JWT_SECRET（≥32 字节随机串）、DEMO_CODE；DATABASE_URL 口令按实际改
notepad .env

# 4) 依赖 → 迁移 → 种子 → 构建 → 启动
npm ci
npx prisma generate
npx prisma migrate deploy      # 2 个迁移：init、uk_workout_user_date
npm run seed                   # 2 用户 / 6 计划 / 72 动作
npm run build
npm run start:prod             # 8094；或回到项目根跑 scripts\start_all.ps1 一键全做

# 5) 自证
curl http://127.0.0.1:8094/api/health          # {"status":"ok","db":"up"}
curl http://127.0.0.1:8094/api/app/version     # 1.0.2 / buildNo 3
curl -I http://127.0.0.1:8094/apk/rn-workout-1.0.2.apk   # 200 + 77,412,373

# 6) 前端真机联调（可选：只想装 APK 演示可跳过）
cd ..\frontend
npm ci
$env:EXPO_PUBLIC_API_BASE_URL="http://<电脑局域网IP>:8094/api"
npm start                      # Expo dev server 8096
```

> 一键脚本：`scripts\start_all.ps1`（起容器 → 等 healthy → migrate deploy → seed → build → 启动 → health 断言）；`scripts\stop_all.ps1`（停后端 + `docker compose stop pg`，**不删数据卷**）。

### 2.3 环境变量（后端 `.env`）

| 变量 | 必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | `postgresql://postgres:<pwd>@127.0.0.1:5434/rn_workout?schema=public` |
| `PORT` | 是 | 8094（端口表登记值） |
| `TZ` | 是 | `Asia/Shanghai`（统计「本周」按本地时区） |
| `NODE_ENV` | 是 | dev/production；production 不注册 Swagger |
| `JWT_SECRET` | 是 | 缺失启动失败（`app.module.ts` 启动校验） |
| `JWT_EXPIRES_IN` | 是 | `7d` |
| `DEMO_CODE` | 是 | 演示验证码 `123456`（**仅演示**，见 Q-018） |
| `SEND_CODE_COOLDOWN_SEC` | 是 | 60（进程内频控，见 Q-024） |
| `RN_CACHE` | 否 | `memory`（统计缓存进程内 Map；多实例需 Redis，偏差 3） |
| `APP_VERSION` / `APP_BUILD_NO` / `APK_URL` / `APP_NOTES` | 否 | 仅当 `release.json` 字段缺失时兜底 |
| `RELEASE_FILE` | 否 | 覆盖 release.json 路径（默认项目根；`paths.ts` 锚点解析） |

前端构建期变量：`EXPO_PUBLIC_API_BASE_URL`（显式指定 API 根）、`EXPO_PUBLIC_PERF_FIXTURE=1`（C02 100 条夹具）。

### 2.4 数据库初始化与种子

- 迁移：`npx prisma migrate deploy` → `20261123092126_init`（5 表）+ `20261124090000_uk_workout_user_date`（`(user_id, log_date)` 唯一）
- 种子：`npm run seed` → users 2（139 普通 / 138 管理员）、plans 6、exercises 72（每计划 12）
- 干净基线：`2 / 6 / 72 / 0 / 0`（users/plans/exercises/workout_logs/set_logs）
- 重置（危险）：`npx prisma migrate reset --force` 会清库重放迁移，**先备份**（第 7.5/9 步均有 `.sql` 备份样例）

### 2.5 APK 更新与回滚

- 出新版：改 `release.json`（version/buildNo/apkUrl/notes）→ 前端 `app.json` 版本同步 → `eas build -p android --profile preview` → APK 落 `10_交付/apk/` → `/api/app/version` 与 `HEAD /apk/...` 双断言
- 回滚（版本）：把 `release.json` 改回上一版（1.0.1 / build 2）+ 保留旧 APK 文件即可；App 侧「不弹更新」自动恢复
- 回滚（数据）：`docker compose stop pg` → 用备份 `.sql` 恢复到 `pg_data` 卷 → 起容器；数据卷不删
- 回滚（代码）：`git revert` 至上一个 release commit（1.0.2 对应 `70659c1` 之后文档提交，代码面 `70659c1`）
