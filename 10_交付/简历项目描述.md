# 简历项目描述 · rn-mobile-app-release（训练台账）

> 版本：1.0.2 · 交付：2026-11-25 · 路线：生产（step1–10.6）
> 数字来源：`08_测试/基线指标验证表.md`、`09_验收/最终验收清单与报告.md`、`08.5_安全扫描/docs/安全扫描报告.md`、`07_联调/联调检查清单.md`、`10_交付/发布记录.md`。**不含** `01_项目基线说明书.md` 的目标值。

## 一、一句话

训练打卡双端 App：Expo/RN + NestJS/PostgreSQL，5 表 20 端点，APK 真机可装、可覆盖升级。

## 二、S 背景

简历缺「生产级移动 App」这条证据，G8 四份 JD 把 RN、Node 后端、PostgreSQL 建模、权限、发布链都写成 must。约束是 16GB 内存、无 Mac、无 Android 开发者账号：只能在本机跑后端与 Metro，APK 交给 EAS 云端出包，iOS 停在 Expo Go。

## 三、T 目标

1. 六页业务闭环 + 4 组接口、≥18 端点（实测 20）。
2. 1 个 APK 能装进 Android 真机；1.0.0→1.0.1 覆盖升级后登录态保留。
3. 普通号越权访问 admin 接口必须 403；安全扫描 P0/P1 归零。

## 四、A 动作

- 用 Expo 58 + React Navigation 搭 AuthStack / MainTabs / Stack，7 屏共用 `apiClient` 单出口（8s 超时、GET 重试一次、401 清登录态），页面不裸 `fetch`；选它是因为无 Mac、无 Android SDK，Expo 能直接出 APK 并用真机装。
- 后端 NestJS + Prisma 建 5 表，把「一天一练」和「同组幂等」压到数据库层：`(user_id, log_date)` 与 `(workout_log_id, exercise_id, set_no)` 复合唯一；同日重复开练复用同一 workoutId，不靠应用层判断。
- 组次录入做乐观回填，失败行标红可重试；结束训练后按钮改「已完成（已锁定）」并弹中文 Toast，修掉真机「点了没反应」。统计用本地周一起算的参数化 `$queryRaw`，不用滚动 7 天近似。
- 版本信息读项目根 `release.json`（带锚点路径解析），后端同时托管 `/apk` 静态目录，App 冷启动调 `/api/app/version` 判断更新；EAS 构建放在仓库外纯 ASCII 目录，绕开 Windows 子目录把路径写成反斜杠的问题。

## 七、D 可演示点（第 9 步真实走通）

1. 登录 → 计划三卡（今日腿日高亮）→ 开练 → 步进 / 勾完成 / 结束锁定：一条主流程约 90 秒。
2. 统计页本周天数、总容量与 PG 实际数据一致；4 周柱无数据周显示 0 不报错。
3. 普通号「我的」看不到管理入口；admin 进「管理后台」只读全站、手机号脱敏；普通号直接调 admin 接口返回 403/40301。

## 八、E 诚实边界

鉴权是演示级：全局共享验证码，知道码就能用任意手机号登录（含 admin），登录无失败次数限制；全站 HTTP，无 HTTPS；数据库容器监听 `0.0.0.0:5434` 且口令是默认值，只能局域网演示，**不能直接上生产**。Redis 缓存降级为进程内 Map；iOS 只在 Expo Go 里跑过，没有 ipa；没有录演示视频，交付包里是 3 分钟演示脚本。`_问题台账.md` 里 20 条 deferred（P2 3 / P3 17）就是上面这些边界的明细，包括断网回滚与双档宽度未真机验证（Q-025/Q-026）。
